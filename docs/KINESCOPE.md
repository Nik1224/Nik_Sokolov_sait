# Каталог роликов с Kinescope

Ролики живут на Kinescope, а не файлами в репозитории. Чтобы не открывать
кабинет ради каждого идентификатора, раскладка оттуда выгружается в
`content/kinescope-catalog.json`. Это справочник, а не содержимое сайта:
страницы по-прежнему собираются из `content/seed`.

## Что внутри

Категории — это проекты Kinescope, как они названы в кабинете. У каждого ролика
записано:

| Поле | Зачем |
| --- | --- |
| `videoId` | Короткий идентификатор для поля `videoId` схемы медиа. Из него `embedUrl` в `lib/media.ts` собирает адрес плеера |
| `embed`, `watch` | Готовые адреса: встраивание и просмотр в кабинете |
| `durationSeconds` | Идёт в `durationSeconds` медиа и в разметку `VideoObject` |
| `resolution` | Кадр исходника. По нему видно, горизонтальный ролик или вертикальный (Reels) |
| `poster` | Постер сервиса. На сайт он не идёт: там первый кадр, обычно пустой зал. Нужен только чтобы опознать ролик глазами |
| `kinescopeId` | UUID записи в API. Для встраивания не годится, нужен при запросах к API |

`kinescopeId` и `videoId` — разные вещи. В разметку страниц идёт только
`videoId`.

Три личных проекта в выгрузку не попадают вовсе: «Свадьба моя», «Макс Терских», «Евгений
Терешин». Они личные и на сайт не идут. Список исключений задан в
`scripts/kinescope-catalog.mjs`: скрипт к этим проектам не обращается вовсе.

## Как обновить

```sh
KINESCOPE_API_TOKEN=<токен> node scripts/kinescope-catalog.mjs
```

Токен выпускается в кабинете: настройки рабочей зоны → «API-токены»
(`https://app.kinescope.io/workspace/api_token`). Прав на чтение достаточно.
Токен в репозиторий не коммитится: `.env*` в `.gitignore`, в `.env.example`
лежит только пустая строка.

Скрипт забирает лишь метаданные, видеофайлы не скачиваются.

## Как ролики попадают на страницы

`content/seed/kinescope.ts` превращает выгрузку в медиа сайта, а
`content/seed/kinescope-map.ts` говорит, во вкладку какой категории идёт
проект. Список роликов в коде не хранится: перевыгрузили каталог — контент
поехал за ним.

Горизонтальные ролики идут во вкладку «Видео», вертикальные — в «Reels»:
решает соотношение сторон исходника. Подпись берётся из категории, а не из
названия у сервиса: там рабочие имена монтажа вроде `Kollekciya_2025_Gotov`.

Проект, которого нет в таблице соответствия, на сайт не идёт. Такие
перечисляет `kinescopeUnmapped` — это не ошибка, а список съёмок, которым на
сайте пока нет вкладки. Заводить под них категорию самовольно нельзя: это
решение владельца.

Проекты, по которым решение уже есть и оно отрицательное, лежат отдельно в
`KINESCOPE_NOT_PUBLISHED` и в этот список не попадают. Сейчас там Reels и
Reels_NIk: склад вертикальных нарезок вперемешку по темам. Вертикальные ролики
и так лежат во вкладке каждой категории рядом со своей съёмкой, отдельная куча
без темы ничего не добавляет.

Ролики, подобранные руками в других файлах сида, перечислены в
`KINESCOPE_HAND_PICKED` и из каталога повторно не берутся: у них постер вырезан
по выбранному кадру и подпись написана по содержанию.

## Постеры

Постер рисуется до нажатия «play», поэтому он обязан лежать на своём домене:
адрес на CDN сервиса означал бы обращение к Kinescope без согласия посетителя.
Их готовит `scripts/kinescope-posters.mjs` — качает кадр, пережимает в 600,
1200 и 1800 и кладёт в `public/media/kinescope` вместе с манифестом
`posters.json`. Сами ролики не скачиваются.

```sh
node scripts/kinescope-posters.mjs
```

Нужен ffmpeg: им режется кадр из потока, когда постер сервиса не годится.

Сервис отдаёт первый кадр ролика, а первый кадр часто негодный: белый лист
перед проявкой, пустой зал, смаз на движении. Такой постер скрипт не берёт, а
идёт за кадром в сам ролик — на седьмую секунду. К этому моменту вступление
кончилось, а предмет уже в кадре. Если и там смаз, пробуются соседние секунды:
шестая, восьмая, пятая, девятая. У короткой нарезки отсчёт идёт от середины:
седьмая секунда у пятисекундного ролика — это уже уход из кадра.

Скачивается только начало потока до нужной секунды, ролик целиком не тянется:
у трёхминутного фильма это пара мегабайт вместо сотни. Секунда записана в
манифесте рядом с постером (`source: "frame@7s"`) — поменять кадр можно, не
разбирая ролик заново.

Для этого нужен ffmpeg в системе. Без него скрипт скажет об этом и оставит
негодные постеры в списке `weak`; такой ролик на сайт не идёт. Показать
смазанное превью хуже, чем не показать ничего: по этой плитке судят о съёмке.

Сито считает два числа и оба порога подобраны глазами, а не выведены из
теории. Резкость (дисперсия лапласиана) ловит смаз и пустой лист. Пара
«бедно по содержанию и мягко по деталям» ловит то, что резкость пропускает:
тёмный кадр с ярким краем даёт высокую дисперсию на границе, а смотреть в нём
не на что. Числа убирают заведомо негодное; выбрать кадр, который представляет
съёмку, может только автор.

Чтобы вернуть отбракованный ролик, положите свой кадр рядом файлами
`<videoId>-600.jpg` и `<videoId>-1200.jpg`. Скрипт видит готовые файлы, меряет
их, помечает `source: "hand"` и больше не трогает. Так же заменяется и любой
постер, который скрипт пропустил, а глаз забраковал: число `sharpness` рядом с
каждым постером подсказывает, с какого начинать.
