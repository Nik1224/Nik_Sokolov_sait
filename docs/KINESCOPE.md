# Каталог роликов с Kinescope

Ролики живут на Kinescope, а не файлами в репозитории. Чтобы не открывать
кабинет ради каждого идентификатора, раскладка оттуда выгружается в
`content/kinescope-catalog.json`. Это справочник, а не содержимое сайта:
страницы по-прежнему собираются из `content/seed`.

## Что внутри

Категории — это проекты Kinescope, как они названы в кабинете. У каждого ролика
записано:

| Поле | Зачем |
| --- | --- |
| `videoId` | Короткий идентификатор для поля `videoId` схемы медиа. Из него `embedUrl` в `lib/media.ts` собирает адрес плеера |
| `embed`, `watch` | Готовые адреса: встраивание и просмотр в кабинете |
| `durationSeconds` | Идёт в `durationSeconds` медиа и в разметку `VideoObject` |
| `resolution` | Кадр исходника. По нему видно, горизонтальный ролик или вертикальный (Reels) |
| `poster` | Постер сервиса. На сайт он не идёт: там первый кадр, обычно пустой зал. Нужен только чтобы опознать ролик глазами |
| `kinescopeId` | UUID записи в API. Для встраивания не годится, нужен при запросах к API |

`kinescopeId` и `videoId` — разные вещи. В разметку страниц идёт только
`videoId`.

Три проекта в выгрузку не попадают: «Свадьба моя», «Макс Терских», «Евгений
Терешин». Они личные и на сайт не идут. Список исключений задан в
`scripts/kinescope-catalog.mjs`: скрипт к этим проектам не обращается вовсе.

## Как обновить

```sh
KINESCOPE_API_TOKEN=<токен> node scripts/kinescope-catalog.mjs
```

Токен выпускается в кабинете: настройки рабочей зоны → «API-токены»
(`https://app.kinescope.io/workspace/api_token`). Прав на чтение достаточно.
Токен в репозиторий не коммитится: `.env*` в `.gitignore`, в `.env.example`
лежит только пустая строка.

Скрипт забирает лишь метаданные, видеофайлы не скачиваются.

## Чего каталог не заменяет

Постеры для сайта снимаются с исходников вручную и лежат в `public/media`.
Выгрузка даёт ссылки и раскладку, но не обложки: без постера медиа не проходит
проверку схемы в `content/schemas/objects/media.ts`.
