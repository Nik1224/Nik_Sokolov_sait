# Сайт Nikita Sokolov

Фото, видео и визуальное производство. Архитектура из ТЗ (ред. 2.0):
**START → PRIVATE / BUSINESS / PRODUCTION**, у каждого направления собственная
Home, RU/EN — полноценные локализации.

Текущее состояние: выполнены этапы 1–3 ТЗ (каркас, прототип, типы контента).
Что осталось за границей этих этапов — в разделе [Не сделано](#не-сделано).

## Запуск

```bash
npm install
npm run dev
```

Сайт откроется на `http://localhost:3000`. CMS для запуска не нужна: пока
реквизиты Sanity не заданы, данные берутся из файловых фикстур
`content/seed`. Все такие записи помечены `isDemo` и в production не
публикуются.

| Команда | Что делает |
|---|---|
| `npm run dev` | Дев-сервер |
| `npm run build` | Продакшн-сборка (включает проверку типов) |
| `npm run typecheck` | Только проверка типов |
| `npm test` | Unit-тесты (Vitest) |
| `npm run test:e2e` | E2E и доступность (Playwright + axe) |

## Подключение CMS

1. Создайте проект на [sanity.io](https://sanity.io) и получите `projectId`.
2. Скопируйте `.env.example` в `.env.local` и заполните переменные.
3. Перезапустите dev-сервер. Редактор откроется на `/studio`, сайт начнёт брать
   данные из CMS вместо фикстур.

Секреты хранятся только в переменных окружения и никогда не попадают в
репозиторий.

## Выкладка на Vercel

Сборка не требует ни ключей, ни CMS — проверено сборкой с пустым окружением.
Связь работает без единой переменной: сайт уводит человека в мессенджер, а не
шлёт письма. Задать стоит только домен.

| Переменная | Значение | Что сломается без неё |
|---|---|---|
| `NEXT_PUBLIC_SITE_URL` | `https://<домен>` | Ничего: подставится домен, который сообщает Vercel. Задать стоит, когда появится свой домен |

`RESEND_API_KEY` и `CONTACT_RECIPIENT` больше не нужны — формы на сайте нет.
Их можно удалить из настроек Vercel.

### Как выложить новый код

Кнопка **Redeploy** пересобирает **тот же коммит**, к которому привязана
выкладка, — новый код она не подхватывает. Это неочевидно и стоило нам трёх
сборок подряд: исправления лежали на GitHub, а собирался первый коммит.

Свежий код попадает на прод одним из двух способов:

- `git push` в `main` — Vercel создаёт новую выкладку сам;
- **Deployments** → открыть запись, у которой в **Source** нужный коммит.

Проверять всегда по строке `Cloning ... (Commit: …)` в начале лога: там видно,
что собирается на самом деле.

Предупреждения npm в логе сборки (`deprecated uuid`, `allow-scripts esbuild`)
приходят из зависимостей Sanity и на сборку не влияют.

## Как всё устроено

```
app/[locale]/                    START; корневой layout задаёт lang
app/[locale]/[direction]/        Home ветки и все её разделы
components/global/               Шапка, футер, переключатели, крошки
components/content/              Карточки, секции, hero, стоимость, связи
components/templates/            Шаблоны листингов и страниц записей
components/media/                Изображения, галерея, видео с consent
content/schemas/                 Схемы Sanity — контракт контента
content/queries/                 Слой доступа к данным (Sanity ↔ фикстуры)
content/seed/                    Demo-данные
lib/                             Роутинг, i18n, SEO, медиа, аналитика, формы
styles/                          Дизайн-токены и глобальные стили
tests/                           Unit, E2E, доступность
```

Три ключевых правила архитектуры:

- **URL — источник истины.** Язык и направление читаются из адреса; никакой
  автоматической подмены по прошлому выбору. Адреса строятся только через
  `lib/routing.ts`.
- **Один шаблон на три ветки.** Cases, Work и Portfolio — один контентный тип
  в разных направлениях; блог — одна коллекция с полем `directions[]`.
  Дублирующих приложений нет.
- **Компоненты не знают про CMS.** Страницы обращаются только к
  `content/queries`. Переключение Sanity ↔ фикстуры происходит в одном месте —
  `content/queries/source.ts`.

## Решения, зафиксированные до разработки

| Вопрос | Решение |
|---|---|
| Адрес статьи | Контекстный `/{locale}/{direction}/blog/{slug}`; canonical ведёт на адрес основного направления |
| Нет EN-перевода | Показываем русскую версию с видимой меткой. Режим единый для всего сайта, переключается в `lib/i18n/localize.ts` |
| Корень `/` | Показывает START на русском (внутренний rewrite на `/ru`), canonical — на `/ru`. Редиректов по прошлому выбору нет |
| Фильтры листингов | Через query (`?category=`, `?type=`), чтобы slug записи оставался уникальным адресом |
| Sticky-шапка | Включена. Требует подтверждения владельцем (§7: «sticky по согласованию») |
| Десктопное меню | С 1024 px. На 768–1023 px — упрощённое меню, как требует §11 |

## Связь

Формы заявки на сайте нет. Кнопка «Связаться» открывает выбор канала —
Telegram, MAX, WhatsApp, SMS — и уводит сразу в переписку. Почта нигде не
участвует: ни отправки писем, ни ожидания ответа.

Если человек нажал кнопку у калькулятора или на карточке пакета, первое
сообщение уже составлено: тип съёмки, форматы, часы и посчитанная сумма. Текст
собирается в `lib/contact/message.ts`, ссылки — в `lib/contact/channels.ts`,
оба покрыты тестами.

Что стоит знать про сами ссылки:

- **WhatsApp** (`wa.me/…?text=`) и **SMS** (`sms:…?body=`) подставляют текст
  по документации. У SMS iOS требует `&body=` вместо `?body=` — система
  определяется в браузере.
- **Telegram** (`t.me/ник?text=`) подставляет текст в текущих клиентах, но в
  документации это не описано. Если когда-нибудь перестанет — человек просто
  попадёт в чат с пустым полем.
- **MAX** открывать чат с готовым текстом не умеет. Такому каналу сообщение
  кладётся в буфер обмена, и в окне об этом написано прямо.

На случай любого из этих сбоев сообщение всегда видно на экране, рядом кнопка
«Скопировать». Персональных данных сайт не собирает и не хранит — согласие на
обработку больше не требуется.

Каналы редактируются в `content/seed/index.ts` (после подключения CMS — в
документе «Настройки сайта»). Убрать канал — убрать строку: интерфейс
подстроится сам.

## Портфолио: как добавлять материалы

Всё содержимое портфолио живёт в двух файлах и добавляется одинаково.

**Фотографии.** Оригиналы кладутся в `source-media/<папка>`, пережимаются в три
размера (600 для телефона, 1200 для сетки, 1800 для полного экрана) с очисткой
EXIF и складываются в `public/media/portfolio/<категория>`. Список кадров
собирается в `content/seed/portfolio-galleries.ts` по именам файлов.

**Ролики с Kinescope.** Со страницы ролика берутся: размер кадра (1920×1080 —
вкладка «Видео», 1080×1920 — Reels), адрес для встраивания и поток. Постер не
берётся у сервиса: он ставит первый кадр, у половины роликов это пустой зал.
Ролик разбирается на кадры, кадр выбирается глазами, секунда записывается
рядом в комментарии — чтобы потом заменить, не разбирая заново.

**Альбомы.** Ссылка на онлайн-галерею `lokos.pro/disk/…`; название и обложка
берутся из самой галереи (`og:title`, `og:image`). Поле `categorySlug`
решает, где альбом показывается: заполнено — во вкладке этой категории
портфолио, пусто — на странице «Полные свадьбы». Так один альбом не
попадается дважды.

Всё это временно живёт в файлах и переедет в CMS без изменения шаблонов:
поля схем уже описаны в `content/schemas`.

## Организаторам и визитка

Два адреса вне клиентского меню.

`/{locale}/private/partners` — страница для свадебных организаторов. В шапке её
нет: она не для пары. Попасть на неё можно тремя путями — прямой ссылкой,
которую владелец даёт сам, полосой на Home ветки PRIVATE и строкой в подвале.
Механизм тот же, что у «Полных свадеб»: `SECTIONS_OUTSIDE_NAV` в `lib/site.ts`.

Плитки категорий на Home раскрываются кадром **поверх страницы, не двигая её**:
верхние ряды вверх, нижний вниз. Пробовали растить нижний ряд по-настоящему —
страница дёргалась на каждое наведение, а сдвиг ничего не давал.

`/{locale}/nikita` — визитка, которую организатор пересылает паре. Живёт рядом
с ветками, а не внутри, и поэтому приходит без шапки и подвала: их добавляет
только макет ветки. Тему приходится проставлять руками — `data-theme="private"`,
иначе страница открывается тёмной.

Что на визитке: портрет, школа, что входит в съёмку, **только свадьбы** —
кадры, фильмы и рилсы по вкладкам, плюс полные серии. Портрет и семейная
съёмка сюда не идут: страницу открывает пара, выбирающая свадебного фотографа.

Из поиска визитка закрыта (`noIndex`) и в карту сайта не попадает: она
дублирует сайт и без навигации проигрывает ему, зато конкурировала бы за те же
запросы.

### Бэкстейдж

Кадры с площадки — как идёт работа, а не что получилось. Показываются в двух
местах: на Home ветки PRIVATE и на визитке. Пока список пуст, блоков нет нигде:
пустой раздел хуже отсутствующего.

Бэкстейдж лежит у категории, рядом с кадрами и роликами
(`Category.backstage`), и показывается в трёх местах по-разному:

| Где | Что показывается | Почему так |
|---|---|---|
| Home ветки | По одному ролику с каждой категории — первый в списке | Выложить все — значит утопить каждый: человек посмотрит первый и уйдёт |
| Портфолио, вкладка категории | Все ролики этой категории | Человек уже выбрал категорию и смотрит её вглубь. Без фильтра блока нет: страница и так собирает кадры всех категорий |
| Визитка | Все свадебные | Её открывает пара, которая уже решает, и второго захода не будет |

Первый ролик в списке — тот, что уходит на Home. Порядок в
`content/seed/backstage.ts` поэтому значимый.

Ролики живут на Kinescope, а не файлами на своём домене. Это не короткие немые
петли вроде обложек категорий, а фильмы по три-четыре минуты со звуком: в
репозитории они дали бы плюс полсотни мегабайт к каждой сборке навсегда, без
перемотки и без подстройки под скорость сети.

Постеры при этом сняты с исходников на своей машине, а не взяты у сервиса — тот
подставляет первый кадр, а там обычно пустой зал. Секунда каждого кадра
записана в `content/seed/backstage.ts`: чтобы поменять, ролик разбирать заново
не нужно.

Чтобы добавить ещё: залить на Kinescope, прислать ссылку, оригинал положить в
`source-media/Backstage` — постер снимется с него.

**Что на этих страницах обещано и должно выполняться:** папка организатору в
три дня без напоминаний, вертикальный ролик площадки в тот же срок, ключевые
кадры в двух кадрированиях, сет под подачу в издание. Это договорные
обязательства, а не намерения.

Там же названы организаторские 10% и расчёт по счёту через ИП с ЭДО — тихой
строкой в конце, без выноса в заголовок: сказать нужно, торговать этим — нет.

## Как работать экономно

Каждое обращение к модели заново отправляет всю переписку, поэтому длинная
сессия дорожает сама по себе, независимо от размера правки. Что помогает:

- **Присылать ссылки пачкой, а не по одной.** Шесть роликов одним сообщением —
  один цикл разбора, тестов и выкладки вместо шести.
- **Начинать новую сессию под новый блок работ.** Этот файл написан для того,
  чтобы новая сессия входила в курс дела без пересказа.
- **Называть секунду для постера,** если она известна: тогда разбор кадров не
  нужен совсем. Просмотр кадров — самая дорогая часть работы.

## Журнал: свадебные статьи

В журнале PRIVATE восемнадцать настоящих статей. Свадебные живут в
`content/seed/journal-wedding.ts`, портрет, семья и частные события — в
`content/seed/journal-private.ts`. Обложки берутся из портфолио теми же
файлами, что и галереи.

Правило, по которому они собраны: **одна статья — один вопрос**. И поисковик, и
ассистент подбирают под запрос конкретную страницу, а не сайт целиком, поэтому
страница, отвечающая на один вопрос до конца, выигрывает у той, где тот же
ответ лежит третьим абзацем. Отсюда и заголовки: «Сколько часов нужен
фотограф», «Когда будут фотографии», «Что надеть на съёмку».

Часть статей называет цифры со страницы стоимости — 12 000 ₽ за час фото,
110 000 ₽ за десять часов, скидка 10% за фото и видео вместе. **Меняя ставки в
калькуляторе, надо пройтись и по статьям:** они на эти числа ссылаются
текстом, и автоматической связи между ними нет.

Поводом послужили гайды владельца по подготовке к свадьбе. Это не пересказ:
факты там общеотраслевые, а текст написан от лица фотографа — что от
расписания и площадки нужно съёмке. Даты и сезонные тренды выправлены на
сегодняшний день.

**Что нашлось в исходных PDF и что с этим делать.** В файлах есть чужие метки:
подпись «Фотограф: Евгения Волошина» под кадром в «Тайминге» и водяной знак
`seashell_wedding` на трёх страницах «Образа невесты». Похоже, гайд собран не
владельцем. На статьи это не переносится — совпадающих формулировок в них нет,
а факты вроде «на сборы уходит два с половиной часа» никому не принадлежат. Но
если гайд куплен у другого автора, стоит свериться с условиями лицензии,
прежде чем строить на нём публичный контент дальше.

## Чтобы сайт попадал в ответы нейросетей

Задача: когда человек спрашивает ассистента «какого фотографа выбрать в
Москве», в ответе должен оказаться этот сайт. Работы начинаются после
подключения домена — без него ни одна из настроек не имеет смысла.

Сначала о том, как это устроено на самом деле, иначе половина усилий уйдёт не
туда. Ассистенты почти никогда не «читают ваш сайт» в момент вопроса. Они
отвечают из трёх источников: того, что было в обучающих данных; живой выдачи
поисковика, к которому они ходят; и страниц, которые открывают по ссылке из
этой выдачи. Отсюда два вывода. Первый: без обычной поисковой видимости
никакая разметка не поможет. Второй: страница должна не «нравиться», а
содержать факты, которые можно процитировать одной строкой.

### Что уже сделано в коде

Всё это работает и без домена — с доменом просто начнёт приносить пользу.

| Что | Где | Зачем |
|---|---|---|
| Явные правила для краулеров ассистентов | `app/robots.ts` | `User-agent: *` их и так допускает, но хостинги и CDN всё чаще режут эти агенты по умолчанию. Явное правило переживает переезд и заодно документирует решение |
| `llms.txt` | `app/llms.txt/route.ts` | Короткая текстовая карта: кто, что снимает, где, почём, ссылки на разделы и все статьи журнала. Модель читает её целиком, без разбора вёрстки. Всё собирается из тех же данных, что и страницы |
| Расширенный `ProfessionalService` | `lib/seo.ts` | Появились `areaServed`, `telephone`, `sameAs`, `founder` и `makesOffer` с часовой ставкой — поля, из которых собирается карточка ответа |
| `FAQPage` на странице стоимости | `app/[locale]/[direction]/pricing/page.tsx` | Пять вопросов теми словами, которыми их задают вслух, с цифрами в ответах. На странице не показывается: ответы и так есть в ставках и калькуляторе, разметка нужна, чтобы их можно было процитировать |

**Важно:** цифры в разметке берутся из настроек калькулятора, а не вписаны в
код. Телефон и профили — из настроек сайта. Так разметка не сможет разойтись с
тем, что написано на страницах.

### Что осталось в коде

| Что | Зачем |
|---|---|
| `ImageObject` у кадров портфолио | Атрибуция авторства на сами снимки |
| `hreflang` RU/EN и canonical | Частично есть; проверить после появления домена |

### Что делается вне кода — и без этого остальное не работает

Для запроса «какого фотографа выбрать в Москве» ассистент опирается не на
персональные сайты, а на справочники, отзывы и подборки. Поэтому:

- профили в Яндекс Бизнесе и 2ГИС с тем же именем, телефоном и городом, что на
  сайте;
- страница ВКонтакте, связанная с сайтом через `sameAs`;
- присутствие в свадебных каталогах и подборках;
- **одинаковые имя, телефон и город везде** — расхождение в написании
  разваливает связку между источниками, и ассистент перестаёт понимать, что это
  один и тот же человек.

### Чем мерить

Готового счётчика тут нет. Работающий способ — раз в месяц задавать самим
ассистентам десяток настоящих вопросов («свадебный фотограф Москва», «фотограф
на свадьбу за городом» и т. д.) и записывать, кого они называют. Плюс Яндекс
Вебмастер и Search Console после подключения домена: без обычной поисковой
выдачи в ответы ассистентов сайт не попадёт.

Честная оговорка: гарантий здесь не бывает. Ни одна из настроек не обязывает
ассистента упомянуть сайт — они повышают шанс, что он найдёт и сможет
процитировать. Быстрее всего отзываются те ассистенты, что ходят в живой поиск;
то, что попадает в обучающие данные, обновляется месяцами.

## Не сделано

Это этапы 4–7 ТЗ. Каждый пункт заблокирован ответом владельца из §18:

- **Реальный контент и миграция медиа** — нужен реестр работ, оригиналы,
  подтверждённые права и атрибуция. Скрейпить источники запрещено (§9).
- **Аналитика** — точки вызова расставлены в `lib/analytics.ts`, провайдер не
  подключён: система и порядок получения согласия не определены.
- **Видеохостинг** — сейчас facade с обязательным постером и consent для
  стороннего плеера. Выбор Mux / Cloudflare Stream — решение этапа 4.
- **Цены, клиенты, роли, credits, отзывы** — в данных отсутствуют намеренно.
  Соответствующие блоки скрыты или помечены `[КОНТЕНТ К ПОДТВЕРЖДЕНИЮ]`.
- **Юридические документы** — ссылки в футере ведут на действующие страницы
  `lokos.pro/legal-terms` и `lokos.pro/legal-privacy`. При переезде на новый
  домен документы нужно перенести и заменить адреса.
- **Домен, redirects, backup и rollback** — настраиваются на этапе 7. Вместе
  с доменом делается всё из раздела [Чтобы сайт попадал в ответы
  нейросетей](#чтобы-сайт-попадал-в-ответы-нейросетей).

Работа с контентом описана в [docs/EDITOR.md](docs/EDITOR.md).
